Component 4 — exactly what changes

Same Grade 1 Sinhala activities; different data, models, decisions and evidence
BEFORE REFACTORWhat the repository previously did
IMPLEMENTED FOUNDATIONWhat Component 4 now does
1

Activity content

Rounds mainly contain prompt, options and correct answer.

Skill 2 has adaptive variants; other skills mostly do not.

→

Traceable research item bank

309 active canonical records include 97 Skill 1–4 core tasks, reduced-load V1 remediation where valid, and original-level V2 confirmation, with KC tags, stable option IDs, equivalent groups and allowed scaffolds.

2

Response evidence

Main signal is correct/incorrect plus latency and touch counts.

An answer completed after highlighting may still increase mastery as “correct”.

→

Standard learning event

Stores first and final correctness, selected answers, attempts, errors, latency, item/KC identity, assistance and treatment fidelity.

3

Learner estimation

Provisional BKT values are almost identical across KCs.

One global IRT theta mixes visual, phonological and language skills.

→

BKT + IRT/Rasch pipeline

BKT: updates mastery for each Sinhala KC.

IRT/Rasch: updates KC-scoped ability and reports information/SE. Offline calibration fits item difficulty and BKT parameters only after real-data thresholds are met.

4

Support decision

Skill 2 follows hand-coded state machines.

Other skills receive a generic fallback; current C1/C2/C3 gateway values are mocked.

→

Child-safe scaffold policy

A deterministic, auditable policy selects only actions declared by the task adapter.

No unvalidated classifier or bandit is presented as trained on children.

5

Next action in Flutter

Adaptive navigation is explicitly accepted only for Skill 2.

Other activities continue using their local fixed sequence.

→

Shared adaptive contract

All 19 Skill 1–4 activities use semantic commands plus exact V1/V2 navigation; answer pools reflow and the core progress dot remains stable.

6

Stopping and evidence

SE calculation exists but is unused. Decisions may be stored more than once.

No trained-policy evaluation across all skills.

→

Auditable validation path

Stable event/action IDs and expected-item checks prevent duplicate application or bypassing pending V1/V2.

Calibration status, sample counts, holdout loss, uncertainty and stop reasons separate software completion from empirical validation.
